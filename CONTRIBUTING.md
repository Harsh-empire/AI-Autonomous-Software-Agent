# Contributing to AEGIS

Thank you for your interest in contributing to AEGIS! We welcome contributions that improve security, verification accuracy, and developer experience.

## Code of Conduct & Ground Rules

1. **Empirical Honesty:** Never commit fabricated benchmark numbers or synthetic test data. All benchmark figures must be generated by live runs.
2. **Security by Default:** Every endpoint and file-handling routine must maintain strict boundary checking (`safe_join`). Path traversal tests are mandatory for any filesystem changes.
3. **No Hardcoded Secrets:** Never commit API keys, tokens, or local absolute paths (e.g., `C:\Users\...` or `/home/...`).

---

## Development Setup

1. **Fork and clone the repository:**
   ```bash
   git clone https://github.com/<your-username>/AI-Autonomous-Software-Agent.git
   cd AI-Autonomous-Software-Agent
   ```

2. **Create a Python virtual environment:**
   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate

   pip install -r requirements.txt
   pip install pytest httpx bandit
   ```

3. **Install Ollama (Optional for full duels):**
   - Install from [ollama.ai](https://ollama.ai)
   - Pull the default coding model: `ollama pull qwen2.5-coder:7b`

---

## Running Tests

Before submitting changes, ensure all tests pass:

```bash
# Run the complete test suite
pytest tests/ -v

# Run path traversal security gate tests specifically
pytest tests/test_path_traversal.py -v
```

---

## Pull Request Guidelines

1. **Branch Naming:** Create a focused feature branch from `main` or the active dev branch:
   - `feature/your-feature-name`
   - `fix/security-fix-name`
2. **Commit Messages:** Use clear, descriptive commit messages summarizing the intent and changes.
3. **Documentation:** Update relevant markdown files (`README.md`, `docs/`) and docstrings when modifying behavior.
4. **CI Verification:** Ensure GitHub Actions tests pass on both Ubuntu and Windows before requesting review.
